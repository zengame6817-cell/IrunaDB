## カレンダー

メニュー「カレンダー」または #calendar で表示。開催中一覧、月表示、日付ごとの予定、種類・名前の検索、今日へ戻る、公式情報リンク、最新確認時刻を実装。日本時間で日付・開催状態を判定する。

現在の収録は2025-10-17以降の延べ966件。月次予定13か月分（2025-10〜2026-10）と公式お知らせ409ページ・2045記事を初回照合。最古の告知2025-10-16まで確認。カレンダーの件数は開催回・キャンペーンごとで、966種類のイベントという意味ではない。未来分は公式に掲載された予定と、最新告知に記載された週次規則から次の7日間だけ展開した予定を含む。

資料：公式ブログの月次予定 http://irunablog.iruna.jp/?feed=rss2 （2ページを取得）、日本版公式 https://android.iruna.jp/information 。ショップ販売・アバター・ガチャ等の告知は除外。取得本文を実行せず、イベント名・開催日時・出典タイトル・告知日・本文SHA256だけを保存。公式ブログは公式サイトから案内されるHTTP URLを使用。HTTPSは証明書のホスト不一致があり、証明書検証を無効にしない。

data/calendar.json がカレンダーの専用データ。Googleスプレッドシートや既存装備のEVENT_MASTERとは独立しており、スプシへは今回書き込まない。月次予定は開催実績の確定とは別で、画面に「公式月次予定」を明記。週次展開には「公式週次予定」を明記。時刻・開始日・終了日が未掲載なら空欄のまま。開始日不明・終了日不明の項目を無期限の開催中扱いにしない。メンテナンス前後という表記も保持。日付のみの終了日は「終了日」と表示。初回は35件に開始日または終了日の一部未記載があり、別枠で確認可能。

月次記事は固定のパーマリンク。個別お知らせの一覧はページ番号が新着により移動するため、リンク先と合わせて正確な告知日・題名を表示。毎日の履歴再取得で参照ページも見直す。公式サイトの構造変更や新しい日付書式で読み取れない項目があればreviewに残る。月次13か月の欠落、一覧構造の変化、取得失敗は更新全体を失敗させ、既存データを消さない。

## 自動更新

.github/workflows/update-calendar.yml：毎時17分（UTC）の予定＋手動実行＋収集コード等を変更したpushで起動。GitHub側の混雑で時刻が遅れることはある。通常は直近3日より前まで、最低8ページを再確認。毎日日本時間4時台（UTC19時台）は過去1年分を再確認。取得失敗時は3回まで再試行し、途中のデータを保存しない。範囲・形式の検証後、data/calendar.jsonだけを自動コミット。

GitHub ActionsのGITHUB_TOKENによるコミットはPagesビルドを起動しないため、画面は公開mainのカレンダーJSONを直接取り込む。HTML・機能はPagesで公開、予定の更新は再ビルド不要。表示中は10分ごと・再表示時・「更新を確認」で確認。最新データが取れなければ同梱データを表示し、その状態と日時を明記。6時間以上古い場合は更新遅延を表示。サービスワーカーは同梱JSONを通信失敗時の控えとして保持する。

権限は現在のリポジトリ内容の書込のみ。ユーザーのGoogle認証や追加の秘密鍵は使わない。checkout/setup-nodeは公式v7、Node24、追加依存なし。将来リポジトリのActions設定や書込権限が変われば失敗するため、Actionsの実行結果を確認する。
